3. GOAL OF THIS PASS
--------------------
"Does the game actually feel good to play?" Fix the three owner-reported problems: (1) tapping a complaint drops you in
a case screen with no obvious way to take a photo or get back to the street; (2) sidewalks too narrow and obstructed;
(3) houses blocked by cars/trees and the cinematic comedy not discoverable. No new large systems.

4. PROBLEMS / ROOT CAUSES FOUND
-------------------------------
a) Complaint flow: INSPECT opened the full case sheet directly (or the lawn-measure mini game for tall grass); the
   camera was only reachable from a small HUD button; a photo was saved and attached instantly with no preview or
   retake; the case sheet, reinspection panel and lawn game had no Back button (only dismiss/ruling) so the player could
   not return to walking without making a ruling. Escape did nothing.
b) REAL BUG (pre-existing): street.inspect_near() only emitted `visit` for kinds "lawn"/"card". For a "reinspect"
   property the HUD REINSPECT button showed a random flavor quip, so follow-up inspections were not reachable by real
   touch play. Automated bots hid this because they called main._on_visit() directly. Fixed (kinds in ACTIVE_KINDS).
c) Sidewalks: WALK_W was 30 px and the walkable corridor was only 0.8*WALK_W with no verge or lawn tolerance; street
   trees were centred 12 px outside the walk so canopies (r 20-30) covered it visually.
d) Interaction distance was measured to the driveway middle (inside the lot), not a public point. Neighbour-bulb crew
   trucks and some curb cars could poke onto/over neighbouring sidewalks and mailboxes (89 overlaps over 28 days found by the
   new validator).
e) Cinematic system existed but: encounters were suppressed on day 1 (MIN_DAY=2), the push-in was subtle, props and
   vehicles were clipped by the bottom bar, and floats/toasts overlapped it.
f) Degenerate polygon: porch-resident speech bubble used an ellipse whose radius scaled from 0 (engine error
   "Invalid polygon data, triangulation failed", intermittently). Fixed.
g) Newly added HUD header text wrapped one-letter-per-line; "BEST" label wrapped; title lacked COMMUNITIES (earlier pass
   edit never applied). All fixed in the visual QA round of the previous pass (kept here for completeness).

6. MAJOR UX DECISIONS
---------------------
- Progressive disclosure: World -> compact card (one gold primary action) -> camera -> preview -> card with evidence
  ("REVIEW & DECIDE") -> case sheet. The case sheet is no longer the first thing the player sees.
- Primary action rules: no photo -> TAKE PHOTO; photo attached -> REVIEW & DECIDE; reinspection -> INSPECT.
- Case sheet highlights ONE recommended action (WARNING if something is cited, else DISMISS) in gold; others stay available.
- A bad/unusable photo no longer costs score points (a retry, not a punishment).
- Lawn measuring is optional (MEASURE LAWN on the card), not a forced first step; photo evidence suffices.
- Markers say "COMPLAINT"/"REINSPECTION" only; they never encode whether the complaint is valid.
- Comedy remains rare after the first showcase; ruling toast ("Warning issued") now appears after the cinematic.

7. COMPLAINT -> INSPECTION -> CAMERA -> CASE WORKFLOW (AFTER THE CHANGES)
------------------------------------------------------------------------
1. Select/see assignment (Next chip, marker, arrow). 2. Walk to the sidewalk anchor; haptic + chime + "PROPERTY REACHED".
3. HUD button "INSPECT" (or tap the house) -> street emits `visit` -> main._on_visit -> (once per house per day a random
   "visit" encounter may play, 20%) -> PropertyCard (state PROPERTY_CONTEXT). Card: < BACK, tag, address, complaint text,
   gold TAKE PHOTO, VIEW COMPLAINT (expands source/reliability/owner; state COMPLAINT_VIEW), OPEN CASE, MEASURE LAWN (tall grass).
4. TAKE PHOTO -> camera immediately (state CAMERA): address header, EVIDENCE CAMERA, ALBUM, CANCEL, +/- zoom, quality meter,
   big shutter. CANCEL returns to the card. 5. Shutter -> PHOTO_PREVIEW (photo, address, date, quality word, "Recorded: ..."):
   USE PHOTO | RETAKE | TAKE ANOTHER | CANCEL. Nothing is saved until USE/TAKE ANOTHER. 6. USE PHOTO -> card shows
   "Evidence attached - N photos - best Q%" with gold REVIEW & DECIDE. 7. Case sheet (CASE_DECISION) has < BACK -> card.
8. WARNING/DISMISS/HEARING/FINE -> ruling applied -> optional/scripted cinematic -> notification -> back to WORLD.
Reinspection: card primary INSPECT -> reinspection panel (< BACK returns to card) -> choice -> WORLD.

13. HOW THE GUARANTEED EARLY CINEMATIC WORKS
--------------------------------------------
main._force_first_case() (day 1, Settings.tutorial_done false): picks the standard straight lot whose anchor is nearest the spawn point and
overwrites its assignment with a certain, non-borderline tall-grass complaint from "Wozig management inspection"; street.clear_lot_parking()
removes parked cars on it and set_objective() selects it. Trees are kept off its access route by generation/validation. The player's first
WARNING (or fine/hearing) makes sim.pick_encounter return showcase_first (Encounters.pick short-circuits until last_seen has the id; last_seen is
saved in world.encounter_seen). Showcase script: door swings open; "Seriously? You're writing me up over my GRASS?"; player line; "THEN MEASURE STEVE'S!";
sprinklers soak the inspector; "...That's a new timer."; choices Explain / Give a few days / Stay firm; footer queues a board discussion.
Existing mid-game saves also get the showcase once (last_seen lacks the id).

1. PROJECT OVERVIEW
-------------------
"HOA President" is a portrait mobile game (Godot 4.7, GDScript, gl_compatibility renderer, iPhone first).
You are the president of a suburban HOA: walk the subdivision, investigate complaints (allegations, not proof),
photograph evidence, decide, issue warnings/fines, do physical reinspections, run hearings, survive board politics
and annual elections. Developer: ITSpector LLC, North Carolina, USA. Community-management partner/inspiration: Wozig.
The owner gave a very long (104-section) design directive at the start of the session. Direction: polished 2D/
isometric-style gameplay with animated cinematic close-ups; keep all existing simulation depth; do not make the
Wozig portal the main gameplay; no CC&R legal-citation lookup gameplay; no full 3D.

2. CURRENT GAME / DESIGN DIRECTION
----------------------------------
- Core loop: complaint -> travel -> observe -> photograph -> decide -> warning/dismiss -> cure period ->
  physical reinspection -> hearing -> board vote -> fine/dismiss/extension -> long-term consequences.
- Fantasy: "I somehow became HOA President and must survive this neighborhood" (not an "HOA cop").
- Tone: serious administration + ridiculous suburbia; non-graphic slapstick, rare so it stays funny.
- Complaints are allegations; the UI must never reveal the answer ("Complaint", "Concern", never "VIOLATION"
  before the player establishes it).
- Pacing: complexity arrives gradually (events/board calls/legal items gated by day).
